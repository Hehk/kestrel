# Personal review workspace

The PR Diff page now has version-bound **Reviewed** and **Collapse/Expand** controls. This is Kestrel state, not GitHub approvals or viewed-file synchronization.

## Run

Use stable Rust (at least 1.90), Node 24+, and the existing backend configuration:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.128 --locked
npm ci
cargo run --locked --manifest-path backend/Cargo.toml
# In another terminal:
npm run dev
```

`APP_URL` must match the browser origin exactly. Vite proxies HTTP and WebSocket `/api` traffic. Refresh an existing PR from GitHub once: legacy stored diffs deliberately have no trustworthy review identity and cannot be marked reviewed until refreshed.

Review controls are enabled by default; `VITE_REVIEW_ENABLED=false` disables the UI. Set `VITE_REVIEW_AGENT_EXPERIMENT=true` to expose human importance and attributed context. Its **Run demo Rust agent** button creates a deterministic, version-bound demonstration assessment, explicitly labelled as not a code analysis. There is no production agent scheduler.

Offline reload requires a production build served on localhost or HTTPS, including `dist/sw.js` at the origin root. Development Vite does not provide offline app-shell installation. Allow the service worker to install before disconnecting. Previously opened PR data is cached; never-opened PRs still need a connection.

```sh
npx playwright install chromium
npm run test:review:e2e
```

This builds the real application, starts the real Axum backend with an isolated temporary SQLite database, and tests it in Chromium. It needs no GitHub account or credentials and does not touch development data.

## Behavior

- Reviewing collapses; unreviewing opens. Manual visibility does not change reviewed state. Repeating a review decision has no visibility side effect.
- Every action captures the displayed immutable snapshot and file-version ID. Metadata synchronization never refreshes the displayed diff.
- New versions start unreviewed/open. Exact returning versions restore their saved flags, including explicit unreview. A conservative predecessor link supplies the invalidation explanation on hover and keyboard focus.
- Open tabs retain their own visibility. Remote reviewed indicators converge, but another tab cannot collapse or expand the current tab. Reload restores converged saved visibility.
- Search temporarily expands collapsed files without persisting that expansion; clearing the query restores the tab's visibility. Search, copying, file navigation, and virtualization still use the original diff data.
- Causally later commands supersede observed decisions. Concurrent decisions use Automerge's deterministic winner, not browser clocks or server arrival order. Review and importance conflicts expose explicit reassert controls. Fieldwise merges may produce reviewed, expanded files.
- Explicit human importance overrides agent assessments. `inherit` relinquishes it. Contributions are attributed, immutable, version-bound, and idempotent by contribution ID. Multiple independent assessments are retained without inventing a consensus.

## Data flow and trust boundary

`crates/review-core` owns schema, commands, projection, proposals and validation. `crates/review-wasm` exposes that same implementation. TypeScript command/view types are generated by Tsify; API envelopes are generated by the existing OpenAPI script. WASM is lazy-initialized by the route-owned runtime, not stored in pure MVU state. The official JS Automerge package is used only by the isolated compatibility tests.

### Client → server: exact typed proposals, never opaque history

A proposal contains its command, fresh actor, original dependency heads, expected change hash, and protocol version. The journal also records its snapshot ID.

The authenticated server:

1. Resolves `(user, immutable GitHub repository ID, PR number)` using server-owned metadata. Checks origin, account, protocol, payload limits and snapshot/version membership.
2. Forks its canonical document at the **original dependency frontier**, applies the shared human command under the proposed fresh actor, and verifies the resulting change hash.
3. Rejects unknown dependencies, reused/colliding actors, mismatched hashes and agent commands. It never accepts or decodes client-supplied Automerge binary changes.
4. Merges the reconstructed change, saves the full history-preserving document and revision inside `BEGIN IMMEDIATE`, then returns the durable receipt.

This is not command replay at the latest server state: the original causal frontier and resulting hash must match. It preserves the exact offline CRDT change while making losing/conflicting/deleted forbidden operations impossible to smuggle through a final-state validator. Agent contributions are generated by the backend under the separate agent capability; client actor IDs never authenticate an agent.

Each command gets a fresh actor with one change. No actor sequence is shared between writable replicas. Scope is external to the document; document content cannot grant access or change its owner.

### Server → client

The same-origin WebSocket sends full binary documents encoded in JSON plus schema/protocol metadata, persistence revision and acknowledged change hashes. Document imports and local commands are serialized. HTTP waits stay outside that queue, so a stalled agent/retry request cannot block local persistence. Handshake/receipt watchdogs restart stalled sockets, and proposal batches are bounded by both count and encoded byte size. The backend polls durable revisions every three seconds for other processes/agent writes; responses are sent only after SQLite commit. Reconnect uses backoff/jitter and starts a fresh connection. Focus/online signals trigger attempts, not a claim of successful synchronization.

Production transport intentionally does **not** use Automerge's opaque, stateful binary sync protocol. Its interop tests remain useful, but bounded typed reconstruction is the deployed trust boundary.

The server quota is 8 MiB or 20,000 changes per metadata document. Old history is not silently compacted. Quota rejection preserves the local branch; export before an administrator adjusts retention/limits.

## Snapshot identity

`backend/src/review_snapshot.rs` fetches both diff and comparison metadata from immutable `baseSHA...headSHA` URLs, then resolves before objects at the comparison's merge base and after objects at the pinned head. Tree traversal is cached by tree SHA and rejects truncated/missing trees. No mutable branch metadata is mixed into the identity calculation.

The versioned SHA-256 fingerprint includes explicit absent sides, full SHA-1 object IDs, real modes, before/after paths, operation kind and canonical reviewable hunks (context, line numbers, content and missing-newline flags). PR head/base commit IDs do not themselves invalidate file versions. Binary content and out-of-hunk edits are covered by full object IDs. Identical reviewable changes across a rebase retain identity.

Snapshot manifests retain base/head/merge-base commits, hash algorithm, full before/after identity inputs, version IDs and conservative predecessor links. SQLite stores immutable raw diffs alongside manifests and membership records, separately from CRDT metadata. Returning to a stored snapshot also restores its original manifest/lineage; unrelated refreshes preserve predecessor explanations. Copies and additions do not guess lineage. Snapshot history is limited to 512 MiB per workspace; an over-limit refresh fails without replacing the displayed snapshot or deleting older records.

## Browser durability and recovery

`src/review/storage.ts` reads the latest record, performs synchronous WASM mutation, and writes the binary document and journal in **one IndexedDB readwrite transaction**. IndexedDB serializes competing tab transactions; BroadcastChannel is notification only. Local commands become eligible for transmission only after transaction completion. Captured commands finish saving after route disposal; unsaved browser exits get a best-effort warning. A local generation fence prevents pre-discard/recovery actions or stale HTTP replies from modifying a replacement branch. A quota/transaction failure does not publish the candidate, revert another tab's work, or send an undurable change. The checkbox restores the durable value on failure.

Remote imports and acknowledgment retirement also commit atomically before publication. Lost replies leave journal entries pending; retry reconstructs the same hashes, so already saved commands are acknowledged without duplicate changes. Backend revisions are durability receipts, never conflict ordering.

- **Saved locally / pending:** survives reload; network failure does not undo the command.
- **Synchronized:** the server has durably acknowledged the pending hashes.
- **Not saved:** local storage failed; retry the action after freeing space. Uncommitted commands are not promised to survive closing the tab.
- **Session expired:** sign in again; durable local edits remain available.
- **Blocked:** permission, schema, ancestry, validation or quota rejection. No automatic retry of that branch. Explicit Retry can retry after permission restoration.
- **Recover:** explicitly archive the original branch and replay pending typed commands onto an authorized server replica, atomically with the replacement local save. Still-unauthorized targets remain blocked. Export includes the current document/journal and archived recovery branches. No automatic branch reset or broad CRDT undo.

The service worker caches only versioned static app assets. It never caches authenticated API responses. An explicit IndexedDB allowlist caches repository/PR metadata, latest diff responses and immutable opened snapshots, keyed by account. Only responses identified by the backend as that account are cached. Network failures and server outages can use the cache; online 401/403 responses cannot. Cached diffs are labelled. Late responses from previous authenticated-store generations are ignored.

Sign-out clears the cached session marker, not pending review work. Offline review data stays partitioned by account. The UI offers export, a persistent-storage request, and explicit account-wide discard with a warning. Clearing account data notifies other open runtimes. Already submitted changes may still finish saving on the server. Browser eviction is outside the app's control; exports are backups. Offline access cannot detect an online GitHub permission revocation retroactively.

## Verification and remaining limits

- Real-browser test: review/collapse, remote visibility isolation, simultaneous offline tab saves with one tab closed, offline app-shell reload, human/agent precedence, lost receipt plus backend restart, local quota rollback, changed/returning versions, rejected origin/account/protocol/opaque writes, explicit blocked-branch recovery and export, expired-session preservation, independent-device conflict/reassertion, persistence/receipts during a stalled HTTP request, saving across route disposal, account switching.
- Native tests: causal reconstruction/hash identity, conflicts/reassertion, capability checks, interoperability, storage failure, generated schedules and complete fingerprint inputs. An HTTP mock verifies immutable comparison/merge-base/tree ingestion and rebase stability.
- Existing large-diff/search/copy/virtualization tests still run. Bulk Rust projection indexes assessments once rather than rescanning every contribution for every file.

The first release keeps full history and uses full document snapshots, not an incremental journal of binary deltas. The WASM asset is about 2.1 MB raw / 640 KB gzip. Large-history/cold-mobile profiling, a user-facing server archival flow, sequential multi-agent replacement streams, human note amendments/dismissals, and a production agent runner remain follow-ups—not hidden implementations or claims of support.
